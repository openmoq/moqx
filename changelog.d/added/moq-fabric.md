- moqx can start [moq-fabric](https://github.com/Quicr/moq-fabric) instead of MoQ Cluster. `peering.method` selects one method when the process starts, and moq-fabric does not also dial service upstreams. The admin API adds, removes, and restarts a peer and reports each peer's state and metrics. `PUBLISH` and `PUBLISH_NAMESPACE` are announced to peers, and peer announcements are delivered to local `SUBSCRIBE_NAMESPACE` and `SUBSCRIBE_TRACKS` subscribers. A received `PUBLISH_NAMESPACE` is not forwarded. When a local subscribe or a peered subscribe matches that namespace, the relay subscribes the track from the client that published it. Objects use the MoQT subgroup, stream, and datagram encoding of the publisher's draft. The announcement carries that draft, one of moqt-16, moqt-18, or moqt-22, and a publish keeps the first one. moqt-23 is ignored. A relay that joins after a namespace and its empty-name track were both announced receives both, track first, so objects still have a handler. A subscribe pulls the track when it arrives before the publisher or before the track announce, and the publisher is set to forward=1. When the last subscriber leaves, including while a subgroup is still open, and no local client is still forwarding, the publisher is set to forward=0. After the last peering session closes, an open subgroup is sent again as a new stream, so a relay in the middle can restart and both directions resume. A local subscriber that leaves and comes back while that subgroup is still open receives the next object. A publisher that opens the subgroup again is not reset by an object still arriving on the previous stream. A peer withdraw leaves the local publish in place, so a publisher that reconnects still delivers to local subscribers.
